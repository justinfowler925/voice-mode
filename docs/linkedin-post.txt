I spent an evening trying to talk to my Mac without touching it.

The send command fired 8 times. It sent 0 messages.

Not "it didn't hear me." It heard me perfectly, every single time, and did nothing. Those two failures look identical from the chair and have nothing in common as bugs — and macOS keeps the number that tells them apart while showing it in no interface anywhere.

A synthetic bare Return is silently dropped by every Electron app. Claude, Cursor, Slack, VS Code. Cmd+Return, from the identical mechanism, works in all of them.

Same event. Same code path. Opposite result. One modifier key.

It took hours to find, because I made the reasonable inference instead — keystrokes don't work in these apps — and went off to build an accessibility-tree walker that pressed the send button directly. Which works often enough to ship and then fails constantly, because those trees shift with layout.

Three wrong conclusions went into my notes that night, each corrected within the hour. The config is right so it works (twice — the stored settings and the running recognizer are different layers). It works everywhere (written off somebody saying it "seems to work," a hedge I promoted to a verified claim). Keystrokes don't work in Electron.

Same flaw in all three: a conclusion drawn one observation wider than the evidence supported. Cheap to check, expensive to retract — and a bad generalisation early sends the whole investigation down a road, so the dead end you eventually hit reads like confirmation instead of a wrong turn three steps back.

The working setup is one line of config. Apple Voice Control listening continuously, one phrase bound to Cmd+Return. It replaced four background daemons, eleven helper apps, and a local speech engine that had never successfully transcribed a single word.

None of it is documented, which is why it took an evening. There is no SDK, no framework, no entitlement. Commands live in one undocumented plist whose per-command schema — the field deciding whether yours works or fires forever doing nothing — is written down nowhere. No community repo of shared command sets exists either, and a widely-copied claim that macOS has no custom vocabulary is simply false.

voice-mode is public now: the complete .voicecommands format, derived by reading a live table and writing to it until every field's behaviour was known. Four mechanism tiers, so you can predict which of your commands will fail. The undocumented notify surface — five recognizer modes, including a code-dictation mode Apple never exposed. And a doctor that reads the counter and tells you which half is broken.

The reusable part has nothing to do with dictation. Reliability is a property of the mechanism you bound to, not the app it lands in.

And the one that keeps earning its keep: the layer reporting success is the one lying. Settings correct. Command fired. Exit code zero. No message sent.
